---
name: Section structure --- reader-objective-first, not code-cataloguing
description: When writing data/methods/empirical sections, open with the empirical objective, then walk the reader through construction as steps that serve that objective. Avoid encyclopedic variable-by-variable cataloguing.
type: feedback
---

When drafting data, sample-construction, or methods sections, do not structure the prose as a list of variables, sources, or code outputs. The reader is not interested in "here is variable X, computed from source Y via formula Z" as a sequence. The reader wants to know: what empirical question is this section serving, what does the data need to deliver to answer it, and how does each construction step move us toward that delivery.

**Why:** User feedback on data section of first-draft-may2026: the section read like a code transcription --- accurate in technical content but oriented to the writer's pipeline rather than the reader's question. Reader-pull > writer-push.

**How to apply:**
1. Open every empirical-substrate section (Data, Sample, Variable Construction, Measurement) with one paragraph stating the empirical objective and what the data needs to deliver. E.g., "The empirical exercise asks whether deposit contestability and bank-level cost or lending edges explain de novo branch entry. To answer it we need..." Then enumerate what is needed at the conceptual level (a clean count of openings, a candidate-market set, bank--market measures of the three hypothesized channels, market controls).
2. Walk the reader through construction in the order that builds toward that goal, not the order the code runs. Each construction step's purpose is justified by what it contributes to the empirical question.
3. Technical details (Call Report item codes, crosswalk filenames, winsorization tails) belong but should be subordinated to the conceptual motion. Keep them tight; do not let them dictate paragraph structure.
4. Avoid "the focal bank's efficiency ratio is the ratio of YTD noninterest expense to..." as a paragraph opener. Open with the measurement target ("To measure a bank's local cost-side advantage, we need..."), then describe the construction that hits the target.

This rule applies to data, identification, and any other section that is fundamentally about measurement infrastructure. Results sections already follow this discipline via the "lead with the claim" rule.
